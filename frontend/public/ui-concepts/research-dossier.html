让多 Agent 协作成为可阅读、可审查的研究过程

这份档案记录了一个具体问题：Producer、Reviewer 与按需子 Agent 应当如何协作，才能避免为了“多 Agent”而增加无效流程。

状态：审核中主责任角色：Producer证据条目：04最后更新：本轮运行

研究问题

当前系统已允许 Producer 与 Reviewer 自主使用只读工具，并保留一级研究委派。但界面中过程信息仍主要出现在聊天时间线，导致最终产物、审核反馈和运行数据不易同时阅读。

协调器应该负责边界和路由；真正的研究与审核循环应保留在 Producer 和 Reviewer 内部。

已确认的证据

  1. 01
    协调器负责有界返工与预算它并不替模型制定研究步骤，因此适合保持轻量。
  2. 02
    Producer 与 Reviewer 均可自主调用只读工具委派是补充信息缺口的手段，而不是每轮任务的必要步骤。
  3. 03
    工作流中间状态只存在于 SSE 投影产品需要把公开步骤转成容易浏览的运行过程，而非复制后台状态机。

建议的产品呈现

将一次工作流视为一份可以继续阅读的档案：正文展示目标、结论和证据；旁栏只保留来源、角色运行与审核记录。工具日志不抢占正文，而作为可追溯的材料保留。

暂定结论

保留 Reviewer 与子 Agent 的按需机制，但让“研究档案”成为用户最终面对的对象：任务目标清楚、结论可读、证据可查、审核意见可定位。
